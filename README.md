# Трекер навчання, лабораторна робота №3. Основи серверної логіки

Трекер навчання з власним сервером на Python (FastAPI). Сайт (React) отримує й зберігає дані через REST API, а сервер працює з базою PostgreSQL у Supabase, яку ви створили в лабораторній №2. API описано специфікацією OpenAPI й перевірено в Postman. Сайт і API запускаються однією командою: сайт відкривається на `http://127.0.0.1:8000`, документація на `/docs`.

## Що вимагає завдання і де це

| Вимога | Де в проєкті |
|---|---|
| Простий бекенд (Python) | `backend/app`, фреймворк FastAPI |
| REST API для отримання й збереження даних | `backend/app/routers`: предмети, сесії навчання, статистика |
| Специфікація OpenAPI | `openapi.json` і `openapi.yaml`, а також жива документація на `/docs` |
| База даних PostgreSQL | Supabase, таблиці `subjects` і `sessions` із лаби №2 |
| Сайт, що працює через API | `frontend` (React), зібраний сайт лежить у `backend/static` |
| Тестування у Postman | `postman/study-tracker.postman_collection.json`, 14 запитів і 26 автоперевірок |

## Усі адреси API

| Метод | Адреса | Що робить |
|---|---|---|
| GET | `/api/health` | Перевіряє сервер і базу |
| GET | `/api/subjects` | Список предметів |
| POST | `/api/subjects` | Створити предмет (201) |
| GET | `/api/subjects/{id}` | Один предмет |
| PUT | `/api/subjects/{id}` | Оновити предмет |
| DELETE | `/api/subjects/{id}` | Видалити предмет із його сесіями (204) |
| GET | `/api/sessions` | Список сесій; фільтри `subject_id`, `date_from`, `date_to`, `limit`, `offset` |
| POST | `/api/sessions` | Додати сесію (201) |
| GET | `/api/sessions/{id}` | Одна сесія |
| PUT | `/api/sessions/{id}` | Оновити сесію |
| DELETE | `/api/sessions/{id}` | Видалити сесію (204) |
| GET | `/api/stats/week` | Підсумки за 7 днів: час, серія днів, прогрес по предметах |

Помилки повертаються з поясненням у полі `detail`: 404 (не знайдено), 422 (дані не пройшли перевірку), 503 (база недоступна).

## Запуск, крок за кроком

**1. Python.** Перевірте в терміналі VS Code:
```
python --version
```
Потрібна версія 3.10 або новіша. Якщо Python немає, завантажте його з python.org і під час встановлення поставте галочку **Add python.exe to PATH**. Потім перезапустіть VS Code.

**2. Папка проєкту.** File → Open Folder → `lab3`. У терміналі перейдіть у серверну папку:
```
cd backend
```

**3. Бібліотеки.** Створіть віртуальне середовище й встановіть залежності (один раз):
```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```
Активувати середовище не потрібно: усі команди нижче запускають Python із `.venv` напряму.

**4. Підключення до бази.** У Supabase натисніть зелену кнопку **Connect** → вкладка **Direct** → у списку Connection method виберіть **Session pooler** і скопіюйте рядок **URI**. Він виглядає так:
```
postgresql://postgres.xxxxxxxx:[YOUR-PASSWORD]@aws-0-eu-west-1.pooler.supabase.com:5432/postgres
```
Замініть `[YOUR-PASSWORD]` на пароль бази, який ви створювали разом із проєктом (дужки теж видаліть). Якщо пароль забули: Project Settings → Database → Reset database password.

У папці `backend` скопіюйте `.env.example` як `.env` і вставте рядок у `DATABASE_URL=...`. Файл `.env` у Git не потрапляє. Session pooler потрібен, бо звичайне пряме підключення Supabase працює лише в мережах з IPv6, а пулер працює скрізь.

Якщо в паролі є спецсимволи (`@`, `/`, `:`, `#`, `?`), їх треба закодувати у рядку, наприклад `@` як `%40`.

**5. Запуск сервера:**
```
.venv\Scripts\python -m uvicorn app.main:app --reload
```
Відкрийте в браузері `http://127.0.0.1:8000`: це сайт трекера. Угорі має бути зелений індикатор «Сервер працює», а дані ті самі, що в лабораторній №2. Спробуйте натиснути **+30 хв** і побачити, як змінюється тиждень. Документація API лежить на `http://127.0.0.1:8000/docs`: це інтерактивна документація (Swagger UI). Розкрийте **GET /api/subjects** → **Try it out** → **Execute**. У відповіді мають бути ті самі предмети, що й на сайті з лаби №2. Зупинити сервер можна комбінацією Ctrl+C.

## Тестування у Postman

1. Завантажте Postman з postman.com. Акаунт не обов'язковий: на екрані входу виберіть **Skip and go to the app** (або **Continue without an account**).
2. Натисніть **Import** і виберіть файл `postman/study-tracker.postman_collection.json`.
3. Запустіть сервер (крок 5). Відкрийте в колекції запит **1. Перевірка сервера** → **Send**. Внизу у відповіді має бути статус `200 OK`, а на вкладці **Test Results** зелені перевірки.
4. Щоб виконати всі запити по порядку, натисніть на колекцію **Трекер навчання API** → **Run** → **Run Трекер навчання API**. Має вийти 14 запитів і 26 пройдених перевірок (passed). Запити створюють тестовий предмет і сесію, змінюють їх, перевіряють помилки 422 та 404 і видаляють усе за собою, тож ваші справжні дані не змінюються.

Якщо сервер працює на іншому порту, змініть змінну `baseUrl` у налаштуваннях колекції (вкладка **Variables**).

## OpenAPI

Специфікація створюється автоматично з коду. Готові файли лежать у корені проєкту: `openapi.json` і `openapi.yaml`. Живий варіант доступний, коли сервер запущено: `/openapi.json`, документація Swagger на `/docs` і ReDoc на `/redoc`. Оновити файли після змін у коді (з папки `backend`):
```
.venv\Scripts\python export_openapi.py
```
Файли можна вставити на editor.swagger.io, щоб побачити специфікацію як документацію.

## Зміни в сайті (необов'язково)

Готовий сайт уже лежить у `backend/static`, тому Node.js для запуску не потрібен. Якщо захочете змінювати вигляд сайту, встановіть Node.js (nodejs.org, версія LTS) і в папці `frontend` виконайте:
```
npm install
npm run dev
```
Сайт для розробки відкриється на `http://localhost:5173`, а запити піде до сервера на порту 8000 (сервер має працювати). Щоб оновити готовий сайт у `backend/static`:
```
npm run build
```

## Типові проблеми

- **`python` не знайдено:** не встановлено Python або не поставлено галочку PATH. Перевстановіть і перезапустіть VS Code.
- **`ModuleNotFoundError`:** запускайте команди саме через `.venv\Scripts\python -m ...`, як у кроках вище.
- **`Не задано DATABASE_URL`:** немає файлу `backend\.env` або він порожній.
- **`password authentication failed`:** неправильний пароль. Перевірте його або скиньте в Supabase (Project Settings → Database).
- **`Tenant or user not found`:** URI скопійовано не повністю. Ім'я користувача має бути `postgres.xxxxxxxx` (з крапкою й кодом проєкту), беріть рядок повністю з Supabase.
- **`could not translate host name` або таймаут:** використано пряме підключення (Direct connection) замість **Session pooler**.
- **`/api/health` повертає 503:** сервер працює, але до бази достукатися не вдалося. Перевірте `DATABASE_URL`.

## Про безпеку

Сервер підключається до бази від імені користувача `postgres` із вашим паролем, тому пароль живе тільки у файлі `.env` і нікуди не публікується. Сам API поки що відкритий для всіх, хто знає його адресу. Вхід користувачів і захист даних з'являться в лабораторній №4. Сайт у цій лабораторній звертається лише до власного сервера й ключів бази не має. Сайт із лаби №2 не змінено, він і далі працює напряму з Supabase. Публікація сервера в хмарі буде в лабораторній №5.

## Розширення сайту (оновлена версія)

Додано: Dashboard за предметами, Pomodoro 25/5 (після завершення можна зберегти сесію), завдання з пріоритетами/дедлайнами/статусами, календар активності за 90 днів, світлу/темну тему, поради на основі статистики та демонстраційну реєстрацію/вхід.

Нові API: `GET/POST /api/tasks`, `PATCH/DELETE /api/tasks/{id}`, `GET /api/calendar`, `POST /api/auth/register`, `POST /api/auth/login`. Документація: `/docs`, `/openapi.json`.

**Важливо:** реєстрація/вхід є навчальною демонстрацією перевірки пароля. Наявні предмети, сесії й завдання залишаються **спільними для всіх користувачів**, а не ізольованими акаунтами. Не використовуйте справжні особисті паролі та не публікуйте застосунок як багатокористувацький сервіс без повної авторизації всіх маршрутів.

### Як побачити новий сайт

У папці `frontend` виконайте `npm ci` та `npm run build`. Збірка автоматично має потрапити в `backend/static` (див. `frontend/vite.config.js`). Після цього запустіть сервер з папки `backend`: `python -m uvicorn app.main:app --reload` і відкрийте `http://127.0.0.1:8000`.

У цьому архіві `backend/static` містить **попередню зібрану версію сайту**, оскільки в середовищі підготовки не вдалося встановити npm-залежності. Усі нові компоненти містяться в `frontend/src`, але перед переглядом потрібна збірка `npm run build`.

Запуск тестів: `cd backend && python -m pytest -q` (18 тестів пройдено на SQLite). Для PostgreSQL потрібен власний локальний файл `backend/.env` на основі `.env.example`; **ніколи не додавайте його до архіву**.
